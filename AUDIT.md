# Site audit — jacobstruzik.com

Date: 2026-07-27

## Stack

- Vite 5 + React 18 SPA, TypeScript, generated by Lovable (`lovable-tagger` in devDependencies, `gptengineer.js` script still loaded in `index.html`).
- Tailwind 3 + shadcn/ui: 49 stock UI components under `src/components/ui/`, nearly all unused.
- Heavy dependency surface for a personal site: 27 Radix packages, framer-motion, recharts, embla-carousel, react-query, react-hook-form, zod, sonner, vaul, cmdk, date-fns, next-themes. The live pages use almost none of it.
- Routing: react-router-dom, client-side only (`BrowserRouter` in `src/App.tsx`).
- Hosting: GitHub Pages via `.github/workflows/deploy.yml` (npm build, deploys `dist/`), custom domain via `public/CNAME` (jacobstruzik.com).

## Rendering / crawlability

- `index.html` ships an empty `<div id="root">` plus two scripts. All content renders client-side. Without JavaScript the page body is empty; only `<title>` and meta description are visible to crawlers that don't execute JS.
- No sitemap.xml, no robots.txt, no JSON-LD, no per-route meta tags (SPA routes share one `index.html`).
- GitHub Pages has no SPA fallback configured, so deep links like `/thoughts/:slug` 404 on direct load anyway.
- External script `cdn.gpteng.co/gptengineer.js` loads on every page (Lovable editor leftover).

## Recommendation

The SPA architecture is the root of the crawlability problem and none of the current code is worth carrying forward (two small pages, both being rewritten). Rebuild on Astro with static output:

- Zero client JavaScript by default; every route is plain HTML at build time.
- First-class markdown content collections for `/writing`.
- Builds to `dist/`, so the existing GitHub Pages workflow needs only a one-line change (swap `npm run build` toolchain). CNAME/domain untouched. GitHub Pages serves static files, so hosting is fully compatible.

Target structure: `/` (intro + links + JSON-LD Person), `/work` (three case studies), `/projects` (one-liners), `/writing` (markdown list + post pages), 404. Sitemap, robots.txt, per-page meta/OG tags, system font stack, single light theme plus `prefers-color-scheme` dark via a few CSS custom properties.
